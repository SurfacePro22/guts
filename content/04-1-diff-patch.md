# Diff와 Hunk (`..` vs `...` 차이), Patch 개념

## 한 줄 정의

- **Diff**: 두 상태(파일·커밋·브랜치) 사이의 차이를 줄 단위로 보여주는 것.
- **Hunk**: diff 안에서 변경된 부분들을 묶은 덩어리 하나. `@@ -a,b +c,d @@`로 시작하는 구간.
- **Patch**: diff 결과를 파일로 저장해, 다른 저장소·다른 시점에 그대로 적용할 수 있게 만든 것.

## 표로 비교 — `A..B` vs `A...B`

같은 표기라도 `git diff`와 `git log`에서 의미가 다르다.

| | `git diff A..B` (= `git diff A B`) | `git diff A...B` |
|---|---|---|
| 비교 대상 | A와 B를 그대로 직접 비교 | A, B의 공통 조상(merge base)과 B를 비교 |
| 보여주는 것 | A→B 전체 차이 (양쪽 다른 변경 다 포함) | B 브랜치가 갈라진 뒤 **B에서만** 일어난 변경 |
| 쓰는 상황 | 두 커밋/브랜치를 있는 그대로 비교하고 싶을 때 | "내 브랜치가 갈라진 이후 뭘 바꿨는지"만 보고 싶을 때 (PR diff와 동일한 방식) |

| | `git log A..B` | `git log A...B` |
|---|---|---|
| 보여주는 것 | B에는 있지만 A에는 없는 커밋 (한쪽 방향) | A, B 어느 한쪽에만 있는 커밋 전부 (대칭차집합, 양방향) |
| 쓰는 상황 | "A 기준으로 B가 몇 커밋 앞서 있나" | "두 브랜치가 서로 뭐가 다른가" (양쪽 다) |

같은 `...`인데 diff는 "한쪽(B)만", log는 "양쪽 다" 보여줘서 헷갈리기 쉬운데, 원리가 다르기 때문이다.

- **diff의 `A...B`**: 비교 기준점 자체를 공통 조상(`merge-base(A,B)`)으로 바꿔서, 그 기준점과 **B 하나만** 비교한다 (`git diff <merge-base> B`와 동일). 비교 대상이 여전히 "두 지점"이라서 결과도 하나(B 쪽 변경)만 나온다.
- **log의 `A...B`**: 커밋 두 개를 비교하는 게 아니라, "A에서 도달 가능한 커밋 집합"과 "B에서 도달 가능한 커밋 집합"을 각각 구해서 그 집합끼리 대칭차집합을 구한다. 그래서 A 쪽 고유 커밋, B 쪽 고유 커밋이 둘 다 나온다.

정리하면 diff의 `...`는 "비교 시작점을 공통 조상으로 옮기는 것"이고, log의 `...`는 "두 커밋 집합의 대칭차집합을 구하는 것"이라 동작 방식 자체가 다르다.

## Hunk 헤더 읽는 법

```diff
@@ -15,7 +15,9 @@ function calculate(a, b) {
 unchanged line
-removed line
+added line 1
+added line 2
 unchanged line
```

- `@@ -15,7 +15,9 @@`: 원본 파일은 15번째 줄부터 7줄, 결과 파일은 15번째 줄부터 9줄이 이 hunk에 포함된다는 뜻.
- `@@` 뒤의 `function calculate(a, b) {`는 이 변경이 속한 함수/블록 이름 (git이 자동으로 찾아서 붙여주는 컨텍스트, 참고용).
- 줄 앞의 `-`는 삭제된 줄, `+`는 추가된 줄, 공백은 변경 없는 문맥(context) 줄.

## Patch 만들고 적용하기

| | `git diff > x.patch` | `git format-patch` |
|---|---|---|
| 내용 | 변경 내용(hunk)만 | 커밋 메시지·작성자·날짜까지 포함한 이메일 형식 |
| 적용 명령 | `git apply x.patch` (내용만 적용, 커밋 안 생김) | `git am x.patch` (커밋 자체를 재생성, 작성자·메시지 보존) |
| 쓰는 상황 | 커밋 없이 변경사항만 옮기고 싶을 때 | 커밋 히스토리 자체를 다른 저장소로 옮기고 싶을 때 |

Cherry-pick(다음 항목)도 내부적으로는 "특정 커밋의 diff를 patch처럼 뽑아서 현재 브랜치 위에 적용"하는 것과 같은 원리다.

## 한 줄 요약

Diff는 차이 전체, Hunk는 그 안의 변경 덩어리 하나이며, `A..B`는 있는 그대로의 비교, `A...B`는 공통 조상 기준 비교(log에서는 양방향 차집합)라는 게 핵심 차이다. Patch는 그 diff를 파일로 저장해 다른 곳에 적용하는 것이다.
