# Merge vs Rebase 비교

## 한 줄 정의

- **Merge**: 두 브랜치의 기존 커밋을 그대로 둔 채, 두 부모를 가진 새로운 "머지 커밋"을 만들어 합치는 것.
- **Rebase**: 내 커밋들을 다른 브랜치 위로 옮겨 새 해시로 재생성해서, 히스토리를 일직선으로 만드는 것 (5-1 참고).

## 표로 비교

| | Merge | Rebase |
|---|---|---|
| 결과 | 두 부모를 가진 merge commit이 새로 생김 | 기존 커밋들이 새 해시로 재생성됨 |
| 기존 커밋 | 그대로 보존 (해시 안 바뀜) | 재작성됨 (해시 바뀜) |
| 히스토리 모양 | 갈래졌다 다시 합류하는 그래프 | 일직선(linear) |
| 충돌 해결 | 보통 한 번 (merge 시점에 몰아서) | 커밋마다 나눠서 여러 번 날 수 있음 |
| 공유 브랜치에 사용 | 안전 (기존 커밋을 안 건드림) | 위험 (황금률 위반 — 이미 push된 커밋은 rebase 금지) |
| 명령 | `git merge <브랜치>` | `git rebase <브랜치>` |

## 히스토리 모양으로 확인하기

```
git log --graph --oneline --all
```

merge를 쓰면 그래프에 브랜치가 갈라졌다 합쳐지는 `*` 노드(머지 커밋)가 보이고, rebase를 쓰면 애초에 갈라진 적 없던 것처럼 일직선으로 이어진다.

## 명령어 치트시트 (5장 — Rebase)

| 명령 | 설명 |
|---|---|
| `git rebase <브랜치>` | 내 커밋들을 다른 브랜치 위로 재적용 |
| `git rebase -i <base>` | 커밋 목록을 열어 pick/reword/edit/squash/fixup/drop 지정 |
| `git commit --fixup=<해시>` + `git rebase -i --autosquash` | fixup 대상 자동 배치 |
| `git rebase --continue`\|`--abort`\|`--skip` | 충돌 시 계속 / 취소 / 건너뛰기 |
| `git merge <브랜치>` | 두 브랜치를 머지 커밋으로 합치기 |
| `git log --graph --oneline --all` | 히스토리가 갈래졌는지 일직선인지 시각 확인 |


## 한 줄 요약

Merge는 기존 커밋을 건드리지 않고 두 히스토리를 있는 그대로 합치는 안전한 방법이고, Rebase는 히스토리를 깔끔한 일직선으로 만들어주는 대신 커밋을 재작성하므로 이미 공유된 브랜치에는 쓰면 안 된다.
