# Submodule이란?

## 한 줄 정의

- **Submodule**: 한 Git 저장소 안에 다른 Git 저장소를 통째로 포함시켜서, 독립적으로 버전 관리되는 하위 프로젝트로 참조하는 기능.
- 부모 저장소는 서브모듈의 실제 코드를 담는 게 아니라, "이 경로에는 이 커밋 해시 시점의 서브모듈이 있다"는 **포인터 하나**만 기록한다.

## 표로 비교 — 자주 쓰는 명령어

| 명령 | 역할 |
|---|---|
| `git submodule add <url> <경로>` | 새 서브모듈 추가 (`.gitmodules` 파일에 기록됨) |
| `git clone --recurse-submodules <url>` | 부모 저장소를 clone하면서 서브모듈 내용까지 함께 받아오기 |
| `git submodule update --init --recursive` | 이미 clone한 뒤라면, 비어있는 서브모듈 폴더를 채워 넣기 |
| `git submodule update --remote` | 서브모듈을 그 자신의 원격 최신 커밋으로 갱신 |
| (서브모듈 폴더 안에서 직접 커밋/푸시) | 서브모듈은 완전히 독립된 저장소라서, 그 안에서 따로 커밋해야 한다 |

## 부모 저장소가 실제로 저장하는 것

부모 저장소에 커밋되는 건 두 가지뿐이다.

- `.gitmodules`: 서브모듈 이름, 경로, url을 적어둔 설정 파일
- **gitlink**: 서브모듈 경로에 대한 특수 트리 엔트리로, 서브모듈의 특정 커밋 해시 하나만 가리킴 (일반 파일이나 폴더가 아니라 "이 커밋을 가리키는 포인터")

그래서 서브모듈 폴더 자체를 처음 clone 직후 열어보면 비어있는 경우가 많다 — 부모 저장소는 코드가 아니라 해시만 알고 있고, 실제 코드는 `git submodule update --init`으로 그 해시에 맞춰 따로 받아와야 채워지기 때문이다.

## 한 줄 요약

Submodule은 부모 저장소 안에 다른 저장소를 특정 커밋 시점으로 고정해서 참조하는 기능이며, 실제 코드가 아니라 커밋 해시 하나만 기록되므로 clone 이후 별도로 초기화·갱신해줘야 한다.
