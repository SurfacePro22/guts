# Stash 대신 Worktree를 써야 하는 이유

## 한 줄 정의

- **Worktree**: 하나의 `.git` 저장소를 공유하면서, 서로 다른 브랜치를 동시에 체크아웃할 수 있는 독립된 작업 디렉토리를 추가로 만드는 기능.
- 원래는 브랜치를 바꾸려면 지금 작업을 커밋하거나 stash로 치워둬야 했지만, worktree를 쓰면 그럴 필요 없이 새 디렉토리에서 다른 브랜치를 바로 작업할 수 있다.

## 표로 비교 — Stash로 전환 vs Worktree 사용

| | Stash로 브랜치 전환 | Worktree 사용 |
|---|---|---|
| 지금 하던 작업 | 임시로 치워둠 (`stash pop` 잊으면 유실 위험) | 그대로 유지됨 (다른 디렉토리라 안 건드림) |
| 전환 방법 | `git stash` → `checkout` → 나중에 `git stash pop` | `git worktree add <경로> <브랜치>` 후 그 디렉토리에서 작업 |
| 동시 작업 | 한 번에 한 브랜치만 볼 수 있음 | 여러 브랜치를 서로 다른 폴더에서 동시에 볼 수 있음 |
| 빌드 산출물·의존성 | 브랜치 바꿀 때마다 다시 설치/빌드해야 할 수도 있음 | 각 worktree가 독립된 디렉토리라 그대로 유지됨 |
| 실수 위험 | stash가 여러 개 쌓이면 헷갈리고, pop 충돌 가능 | 애초에 전환할 필요가 없어 실수 자체가 줄어듦 |

## 명령 예시

```
git worktree add ../hotfix hotfix-branch   # ../hotfix 디렉토리에 hotfix-branch를 체크아웃
cd ../hotfix                               # 별도 디렉토리 — 원래 작업 디렉토리는 그대로
# ... 여기서 급한 수정 작업 ...

git worktree list                          # 지금 연결된 worktree 목록 확인
git worktree remove ../hotfix              # 다 쓰면 제거
```

원래 작업 디렉토리에서는 여전히 원래 브랜치, 원래 커밋되지 않은 변경사항이 그대로 남아있다 — stash를 한 번도 쓸 필요가 없다.

## AI 에이전트와 함께 쓰기 좋은 이유

Claude Code 같은 AI 코딩 에이전트를 여러 개 동시에 돌리거나, 에이전트가 작업하는 동안 나도 같이 다른 작업을 하고 싶을 때 worktree가 잘 맞는다. 에이전트마다 독립된 폴더 + 독립된 브랜치를 주면, 서로 파일을 건드릴 일이 없기 때문이다.

| | 장점 | 단점 |
|---|---|---|
| 동시 실행 | 에이전트 A, B가 각자 다른 worktree/브랜치에서 작업 — 파일 충돌 없음 | 브랜치 하나는 worktree 하나에만 체크아웃 가능. 에이전트마다 별도 브랜치를 미리 만들어줘야 함 |
| 실패한 시도 처리 | 마음에 안 들면 그 worktree 폴더만 통째로 지우면 끝 (`git worktree remove`), 원본 브랜치는 안전 | worktree가 늘어날수록 "어떤 폴더가 어떤 브랜치인지" 관리 부담 증가 |
| 자원 효율 | 같은 `.git` objects를 공유해서, 풀 클론 여러 개보다 디스크·생성 속도에서 가벼움 | `node_modules` 같은 의존성은 worktree마다 따로 설치해야 해서 그 부분은 오히려 중복됨 |
| 격리 수준 | 워킹 디렉토리·Index는 완전히 분리됨 | hooks·일부 config는 저장소 전체에 공유되므로 완전히 독립된 샌드박스는 아님 |
| 병렬 리뷰 | 사람은 원래 폴더에서 리뷰·테스트하는 동안 에이전트는 다른 폴더에서 계속 작업 가능 | 실수로 다른 worktree인 줄 모르고 커밋하면 브랜치를 헷갈릴 수 있음 |

즉 "가볍게 여러 벌의 작업 공간을 만들어서, 서로 간섭 없이 병렬로 굴린다"는 점에서 여러 AI 에이전트를 동시에 쓰는 워크플로우와 잘 맞지만, 브랜치를 미리 나눠야 하고 완전한 샌드박스는 아니라는 한계도 같이 알아야 한다.

## 한 줄 요약

Stash는 지금 작업을 임시로 치워두고 브랜치를 전환하는 방식이라 유실 위험과 번거로움이 따르지만, Worktree는 같은 저장소를 공유하는 별도 디렉토리에서 다른 브랜치를 동시에 작업할 수 있어 애초에 전환 자체가 필요 없어진다.
